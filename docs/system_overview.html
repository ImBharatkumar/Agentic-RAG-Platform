📥 Ingestion Subsystem

Converts raw PDFs into searchable, context-enriched vector embeddings.

  • Docling OCR Layout Analysis
    PDFs are parsed into structured Markdown, extracting complex tables and headings.
  • Contextual Chunking
    A 50–100 token document summary header is prepended to each chunk before embedding to prevent context loss.
  • Dual-Index Storage
    Stores 768-dim embeddings in pgvector alongside tsvector full-text search strings.

🤖 Agentic Reasoning Subsystem

Cyclical LangGraph workflow that guarantees answer grounding.

  • Query Analysis & Co-reference
    Classifies intent (retrieve vs generate) and rewrites ambiguous references (e.g. "what about that clause?").
  • Hybrid RRF Search
    Queries dense and sparse indices, fusing the ranks via Reciprocal Rank Fusion ($k=60$).
  • Self-Reflection Gate
    Validates if retrieved chunks contain sufficient answers. Triggers query refinement if needed.

Restoring Chat History (`GET /sessions/{thread_id}/history`):

When the user refreshes the page or switches sessions, React fetches /sessions/{thread_id}/history, which reads the current state snapshot directly from PostgreSQL without re-running any LLM inference.

⚡ Real-Time Token-by-Token Streaming Architecture

Instead of waiting for the full LLM response (which would cause a 5-10 second perceived delay), tokens are streamed to the user interface in real-time as they are synthesized.

┌─────────────────────────┐ │ ChatOllama Model Stream │ (Emits tokens as generated) └────────────┬────────────┘ │ token ▼ ┌─────────────────────────┐ │ StreamingTokenHandler │ (LangChain BaseCallbackHandler) └────────────┬────────────┘ │ q.put(token) ▼ ┌─────────────────────────┐ │ Thread-Safe Queue.Queue │ (Decouples LangGraph thread from HTTP ASGI loop) └────────────┬────────────┘ │ q.get() ▼ ┌─────────────────────────┐ │ FastAPI StreamingResp │ (media_type="text/plain", HTTP Chunked Encoding) └────────────┬────────────┘ │ Network Stream Chunks ▼ ┌─────────────────────────┐ │ Browser ReadableStream │ (React fetch + reader.read() loop) └────────────┬────────────┘ │ Typewriter Update ▼ ┌─────────────────────────┐ │ React Message Bubble UI │ └─────────────────────────┘

Implementation Code:

# Inside graph.py: Callback Handler and Worker Thread
class StreamingTokenHandler(BaseCallbackHandler):
    def __init__(self, token_queue: queue.Queue):
        self.token_queue = token_queue

    def on_llm_new_token(self, token: str, **kwargs) -> None:
        if token:
            self.token_queue.put(token)

def run_agent(query: str, thread_id: str = "default"):
    q = queue.Queue()
    config = {"configurable": {"thread_id": thread_id, "token_queue": q}, "recursion_limit": 25}
    inputs = {"original_query": query, "iterations": 0, "messages": [HumanMessage(content=query)]}

    def run_graph():
        try:
            for _ in app.stream(inputs, config): pass
        finally:
            q.put(None)  # Sentinel: marks end of stream

    threading.Thread(target=run_graph, daemon=True).start()

    while True:
        token = q.get()
        if token is None: break
        yield token

🔍 Ingestion & Hybrid RRF Search Mechanism

Dense semantic retrieval (pgvector) and sparse keyword retrieval (tsvector) are combined using Reciprocal Rank Fusion (RRF).

1. Dense Vector Search (pgvector)

Finds semantically similar concepts even if keywords differ.

SELECT id, doc_id, content, context,
       1 - (embedding <=> :query_vector) AS score
FROM chunks
ORDER BY embedding <=> :query_vector
LIMIT 20;

2. Sparse Full-Text Search (tsvector)

Finds exact entity codes, section numbers, and names.

SELECT id, doc_id, content, context,
       ts_rank_cd(to_tsvector('english', content || ' ' || context), query) AS score
FROM chunks, plainto_tsquery('english', :query_text) query
WHERE to_tsvector('english', content || ' ' || context) @@ query
ORDER BY score DESC
LIMIT 20;

3. Reciprocal Rank Fusion (RRF) Formula ($k=60$)

Normalizes disparate score distributions without needing hyperparameter tuning:

RRF_Score(d) = (1 / (60 + Dense_Rank(d))) + (1 / (60 + Sparse_Rank(d)))

🔮 Future Enhancements & Scalability Roadmap

Strategies to scale the enterprise platform to millions of documents, sub-50ms latency, and enterprise production standards.

1. 🚀 Semantic Caching Layer (Redis / GPTCache)

The Opportunity: 30–50% of enterprise queries are repeated or near-duplicate. Hitting LLM and Postgres for identical queries is wasteful.

Architecture:

  • Store embeddings of incoming queries in Redis with a similarity index.
  • If cosine similarity $>0.96$, return cached answer in <5ms.
  • Include TTL and cache invalidation upon document re-ingestion.

2. 🗄️ Asynchronous Ingestion Queue (Celery / Redis Queue)

The Opportunity: Large PDF ingestion with Docling and embedding can take 30+ seconds for 100-page manuals.

Architecture:

  • Decouple upload from processing via background worker tasks.
  • Return instant task_id with WebSocket status updates.

3. 🎯 Two-Stage Reranking (Cross-Encoder / Cohere)

The Opportunity: For high-stakes legal/medical contracts, apply a secondary cross-encoder reranker.

Architecture:

  • Retrieve Top-25 candidates using fast RRF.
  • Rerank down to Top-5 using bge-reranker-v2-m3 or Cohere Rerank.

4. 📊 Full Observability & Tracing (LangSmith / OpenTelemetry)

The Opportunity: Real-time visibility into token usage, node latency, and reflection failure rates.

Architecture:

  • Attach OpenTelemetry spans to each LangGraph node.
  • Export latency and token usage metrics to Prometheus and Grafana dashboards.
